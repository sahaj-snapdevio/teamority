# Internal / historical docs

These documents describe **how Kanbanica was originally built and how it was
prepared for open-source release**. Most are kept purely for historical
reference and are **not required reading** for contributing — the one
exception is `RELEASE_CHECKLIST.md`, which still has open, actionable items
(see below).

For contributor-facing documentation, see:

- [ARCHITECTURE.md](../../ARCHITECTURE.md) — how the system fits together
- [CONTRIBUTING.md](../../CONTRIBUTING.md) — how to contribute
- the feature specs in [`docs/`](../) — task, sprint, permissions, real-time, etc.

## Build history

- `development-plan.md` — the original phase-by-phase build plan
- `revision-plan.md` — retroactive changes to already-built code

## Open-source readiness

Chronological order — each superseded doc says so at the top and links forward:

- `documentation-audit.md` — the earliest documentation quality audit (superseded)
- `OPEN-SOURCE-READINESS-AUDIT.md` — the original open-source readiness audit that kicked off the conversion (superseded)
- `OPEN-SOURCE-IMPLEMENTATION-ROADMAP.md` — the execution plan derived from that audit (superseded)
- `OPEN-SOURCE-PROGRESS.md` — a point-in-time progress snapshot against the roadmap (superseded)
- `OPEN-SOURCE-RELEASE-REPORT.md` — **current status summary** — start here for "where are we"
- `RELEASE_CHECKLIST.md` — **current, actionable** — the release checklist itself; still has open items
